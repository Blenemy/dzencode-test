# Inventory — приходы и продукты

Тестовое задание dZENcode «SPA-приложение: Orders & Products» (уровень Middle).

**Прод:** https://dzen.topchyidev.shop

> Проект в разработке. Полное описание функций, архитектуры и соответствия пунктам ТЗ
> появится в этом файле по мере готовности.

## Стек

| Часть          | Технологии                                                                                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| web            | Next.js 16 (App Router, SSR), React 19, TypeScript, Redux Toolkit + RTK Query, next-intl, Bootstrap 5 (SCSS) + BEM, motion, react-hook-form + zod, socket.io-client |

## Быстрый старт (Docker)

Нужен Docker с Compose v2.

```bash
cp .env.example .env
docker compose up -d --build
```

Приложение: http://localhost:8080, проверка API: http://localhost:8080/api/health,
документация API (Swagger): http://localhost:8080/api/docs.

Демо-доступ: `demo@dzen.test` / `demo12345` (создаётся автоматически).

Стек из пяти контейнеров:

| Сервис    | Назначение                                                                |
| --------- | ------------------------------------------------------------------------- |
| `mysql`   | MySQL 8.4, порт опубликован только на `127.0.0.1:3307`                    |
| `migrate` | одноразовый: применяет миграции Prisma, создаёт демо-пользователя         |
| `api`     | Express на порту 4000 внутри сети                                         |
| `web`     | Next.js standalone на порту 3000 внутри сети                              |
| `gateway` | nginx: `/` → web, `/api` и `/api/socket.io` → api, `/uploads` — из volume |

## Разработка с хоста

Нужны Node.js 22 и Docker (только для MySQL).

```bash
npm install
cp .env.example .env
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env.local
npm run dev
```

`npm run dev` поднимает MySQL в Docker, собирает `packages/shared` и запускает api (http://localhost:4000)
и web (http://localhost:3000) с перезагрузкой при изменениях. Next проксирует `/api` и `/uploads` в
api, поэтому браузер работает с одним origin, как на проде. Socket.io в разработке подключается к
api напрямую (`NEXT_PUBLIC_SOCKET_URL`): прокси Next не пропускает websocket.

## Фронтенд

Страницы: `/login`, `/register`, `/orders`, `/products`, `/groups`, `/users`, `/settings`. Русский —
язык по умолчанию без префикса, английский — под `/en/...` (next-intl, типизированные сообщения в
`apps/web/messages`).

- **SSR и защита страниц.** `proxy.ts` пускает в приложение только с сессией и уводит уже вошедших
  со страниц входа. Refresh-кука ограничена путём `/api/auth`, поэтому страницам виден лишь
  безопасный признак `has_session`. Если access-токен истёк, layout на сервере получает 401 и
  показывает `SessionRestore`: клиент обновляет сессию и перерисовывает ту же страницу без редиректа.
- **Состояние.** Redux Toolkit: store создаётся на каждый запрос, пользователь приходит из SSR.
  RTK Query ходит в REST через `fetch`; на 401 выполняется один общий refresh для всех параллельных
  запросов и повтор запроса.
- **Приходы.** `/orders` — список с числом продуктов, датой в двух форматах и суммами в USD и UAH.
  `/orders/:id` открывает панель прихода рядом со списком: ссылку можно открыть сразу, панель
  рендерится на сервере. Данные, полученные на сервере, кладутся в кеш RTK Query
  (`upsertQueryEntries`), поэтому клиент не запрашивает их повторно. Удаление прихода или продукта
  подтверждается в попапе: его состояние хранится в слайсе `deletion`, сам попап грузится лениво
  (`next/dynamic`). Приход удаляется вместе с продуктами.
- **Продукты.** `/products` — таблица по макету: статус, фото, гарантия, состояние, цены, группа,
  пользователь, приход и дата. На десктопе таблица прокручивается по горизонтали, на телефонах
  превращается в карточки. Фильтры «Тип» и «Спецификация» и номер страницы хранятся в URL
  (`?type=5&spec=…&page=2`): первая загрузка рендерится на сервере, дальше URL меняется через
  `history.pushState`, а данные подгружает RTK Query без перезагрузки страницы. Последние фильтры
  запоминаются в localStorage, и ссылка «Продукты» в меню открывает их сразу.
- **Группы и графики.** `/groups` открывается итогами: число приходов, продуктов и общая
  стоимость. Ниже продукты по группам (группа «Без группы» приглушена) и доля свободных продуктов и
  продуктов в ремонте. Ещё два графика на recharts: продукты по типам и стоимость приходов по
  месяцам. Пустые месяцы показываются нулём, чтобы ось времени была честной. Графики грузятся лениво
  (`next/dynamic`), у каждого есть подсказка при наведении и таблица с теми же данными. Цвет графиков
  `#689f38` проверен на контраст с фоном и различимость при дальтонизме. Данные приходят из
  `/api/stats` и обновляются вживую по событиям Socket.io.
- **Пользователи и карта.** `/users` — сотрудники с аватаром, почтой, складом и числом закреплённых
  продуктов. Склады показаны на карте react-leaflet с тайлами OpenStreetMap, ключи не нужны. На
  маркере число сотрудников, у выбранного склада всплывает карточка с адресом и числом приходов.
  Выбрать склад можно маркером на карте или кнопкой над ней; список фильтруется с анимацией, карта
  плавно приближает склад, а при «уменьшить движение» перемещается без анимации. Leaflet грузится
  лениво и только в браузере.
- **Настройки.** `/settings` состоит из трёх блоков.
  - **Профиль:** имя и аватар; аватар загружается через `/api/uploads` и сразу обновляется в меню.
  - **Интерфейс:** язык, основная валюта и анимации. Основная валюта показывается крупно в
    приходах, продуктах, итогах и на графике, вторая — мелко. «Выключены» отключает и анимации
    motion, и CSS-переходы.
  - **Сессия:** счётчик вкладок, ID вкладки и «Выйти на всех устройствах».
- **Web Storage.** Валюта и анимации хранятся в Redux-слайсе `preferences`, который listener-middleware
  сохраняет в localStorage. Событие `storage` применяет изменения во всех открытых вкладках.
  Фильтры продуктов тоже лежат в localStorage. ID вкладки хранится в sessionStorage: он
  переживает перезагрузку, но у каждой вкладки свой.
- **Realtime и EDA.** `RealtimeBridge` держит соединение Socket.io: `sessions:count` обновляет
  счётчик вкладок в TopMenu, доменные события превращаются в Redux-экшены, и listener-middleware
  инвалидирует кеш RTK Query. Удаление в одной вкладке перезапрашивает данные в остальных; если там
  была открыта панель удалённого прихода, она закрывается.
- **Формы.** react-hook-form с теми же zod-схемами из `packages/shared`, что проверяет сервер. Тексты
  ошибок — ключи i18n; ошибки сервера переводятся по `code`, а занятый серийный номер подсвечивается
  у своего поля. Зелёный «+» в заголовке открывает создание прихода; после создания сразу
  открывается его панель. «Добавить продукт» в панели и «+» на странице продуктов открывают форму
  продукта. Фото можно выбрать или перетащить: тип и размер (JPEG, PNG, WebP до 2 МБ) проверяются
  ещё в браузере, на сервере — по сигнатуре файла. Формы живут в модалках, которые грузятся лениво.
- **Стили.** Bootstrap 5 собирается из SCSS только из нужных частей и с цветами макета: npm-скрипт
  `styles` (sass) запускается перед `dev` и `build`. Компоненты оформлены по БЭМ (`top-menu__aside`,
  `nav-menu__link--active`), токены дизайна — CSS-переменные.
- **Анимации** (motion): переход между разделами, подчёркивание активного пункта меню переезжает
  между пунктами, смена числа в счётчике вкладок, выезд и закрытие панели прихода, сжатие списка,
  исчезновение удалённых строк. Учитывается системная настройка «уменьшить движение».
- **Адаптив.** Ниже 992 px меню превращается в выезжающую панель (Bootstrap offcanvas). Ниже 1200 px
  открытая панель прихода занимает всю ширину вместо списка, на телефонах строки перестраиваются в
  две линии.

## API

REST под `/api`, полная спецификация — в Swagger на `/api/docs` (JSON: `/api/openapi.json`).

| Метод  | Путь                  | Что делает                                                                                           |
| ------ | --------------------- | ---------------------------------------------------------------------------------------------------- |
| GET    | `/api/health`         | состояние api и MySQL                                                                                |
| POST   | `/api/auth/register`  | регистрация, сразу выдаёт сессию                                                                     |
| POST   | `/api/auth/login`     | вход по почте и паролю                                                                               |
| POST   | `/api/auth/refresh`   | новая пара токенов по refresh-куке                                                                   |
| POST   | `/api/auth/logout`    | отзыв refresh-токена и очистка кук                                                                   |
| GET    | `/api/auth/me`        | текущий пользователь                                                                                 |
| PATCH  | `/api/auth/me`        | изменить имя и аватар                                                                                |
| DELETE | `/api/auth/sessions`  | выйти на всех устройствах: отзыв всех refresh-токенов                                                |
| GET    | `/api/orders`         | приходы: число продуктов и сумма в USD и UAH                                                         |
| POST   | `/api/orders`         | создать приход                                                                                       |
| GET    | `/api/orders/:id`     | приход вместе с продуктами                                                                           |
| DELETE | `/api/orders/:id`     | удалить приход и все его продукты                                                                    |
| GET    | `/api/products`       | продукты: фильтры `typeId`, `specification`, `status`, `orderId`, поиск `q`, страницы `page`/`limit` |
| POST   | `/api/products`       | добавить продукт в приход (цены в обеих валютах)                                                     |
| GET    | `/api/products/:id`   | продукт                                                                                              |
| DELETE | `/api/products/:id`   | удалить продукт                                                                                      |
| GET    | `/api/product-types`  | типы продуктов                                                                                       |
| GET    | `/api/specifications` | спецификации (для фильтра)                                                                           |
| GET    | `/api/groups`         | группы продуктов                                                                                     |
| GET    | `/api/users`          | пользователи                                                                                         |
| GET    | `/api/warehouses`     | склады с координатами                                                                                |
| GET    | `/api/stats`          | сводка для графиков                                                                                  |
| POST   | `/api/uploads`        | загрузка фото продукта                                                                               |

Всё, кроме `health`, документации и входа/регистрации, требует авторизации. Ошибки всегда в одном
формате: `{ error: { code, message, details? } }`. Интерфейс опирается на `code`, а не на текст.

### Данные

Модель повторяет `app.js` из ТЗ и дополнена полями со скриншотов:

- **Приход** (`orders`): название, описание, дата, склад, автор.
- **Продукт** (`products`): серийный номер, новый/б/у, фото, название, тип, спецификация, статус
  (свободен / в ремонте), гарантия «с … по …», приход, группа, закреплённый пользователь.
- **Цены** (`product_prices`): по строке на валюту, как `price[]` в `app.js`; одна из них по умолчанию.
- Справочники: типы, группы, склады (с координатами для карты), пользователи.

Удаление прихода удаляет его продукты и цены на уровне внешних ключей (`ON DELETE CASCADE`).
Сумма прихода считается одним SQL-агрегатом по валютам.

Сервис `migrate` после миграций запускает сид: демо-пользователь, 8 сотрудников, 5 складов, 6 типов,
5 групп и 25 приходов с продуктами. Набор детерминированный и создаётся, только пока приходов нет.

Фото продукта загружается отдельно (`POST /api/uploads`, до 2 МБ): тип файла определяется по
содержимому, а не по расширению, допускаются JPEG, PNG и WebP. Файлы лежат в volume `uploads`,
их отдаёт nginx-шлюз с долгим кешем.

### События (EDA)

Сервисы не знают, кто реагирует на изменения: после записи они публикуют доменное событие в
типизированную шину (`order.created`, `order.deleted`, `product.created`, `product.deleted`).
На неё подписаны аудит-лог и Socket.io: событие уходит во все открытые вкладки, поэтому удаление
прихода в одной вкладке сразу видно в остальных.

### Realtime (Socket.io)

Сервер Socket.io работает в том же процессе, что и api, на пути `/api/socket.io` (через nginx-шлюз,
с апгрейдом до websocket).

| Событие от сервера | Данные                                   | Когда                                        |
| ------------------ | ---------------------------------------- | -------------------------------------------- |
| `sessions:count`   | `{ count }`                              | при открытии и закрытии любой вкладки        |
| `inventory:event`  | `{ name, payload, actorId, occurredAt }` | после создания или удаления прихода/продукта |

- Счётчик в TopMenu — число открытых вкладок приложения у всех пользователей: каждая вкладка держит
  своё соединение.
- Подключение авторизуется той же httpOnly-кукой `access_token`: без неё или с просроченным
  токеном сервер отвечает `connect_error` с кодом `UNAUTHORIZED` / `TOKEN_EXPIRED` / `TOKEN_INVALID`,
  и клиент обновляет сессию через `/api/auth/refresh`.
- Соединения с чужого `Origin` отклоняются ещё до рукопожатия.
- Один процесс api держит счётчик в памяти. Для нескольких экземпляров api понадобится
  Redis-адаптер Socket.io — архитектура это допускает, но для тестового задания он избыточен.

### Авторизация (JWT)

- Access-токен живёт 15 минут, refresh — 30 дней. Оба лежат в httpOnly-куках, в JSON токены не
  отдаются, JavaScript страницы их не видит.
- Кука `access_token` с `Path=/`: её видят SSR Next.js и Socket.io. Кука `refresh_token` с
  `Path=/api/auth`: она уходит только на эндпоинты авторизации.
- Refresh-токен ротируется при каждом обновлении. В базе хранится только его sha256.
- Повторное предъявление уже использованного refresh-токена считается кражей: отзывается вся
  цепочка сессии. Исключение — 10 секунд после ротации: так две вкладки, обновившиеся одновременно,
  получают одну и ту же новую сессию.
- Пароли — argon2id. Вход для неизвестной почты занимает столько же времени, сколько для известной.
- Изменяющие запросы с чужим `Origin` отклоняются (защита от CSRF), вход и регистрация ограничены
  по частоте с одного IP.

## Тесты

Интеграционные тесты api работают с настоящей MySQL: база `inventory_test` создаётся при первом
запуске контейнера MySQL, миграции к ней применяются перед прогоном.

```bash
docker compose up -d --wait mysql
npm run build -w @dzen/shared
npm run test:api
```

Другая база задаётся через `TEST_DATABASE_URL`. В CI тесты идут на каждый PR с MySQL в
сервис-контейнере.

## Деплой

Push в `main` запускает `.github/workflows/deploy.yml`:

1. те же проверки, что и на PR (`ci.yml`);
2. сборка образов api и web и публикация в GHCR (сборка Next идёт в CI, а не на сервере, где живёт
   ещё один прод);
3. на сервере `git reset --hard origin/main`, `docker compose pull` и `up -d --no-build`;
4. проверка `https://dzen.topchyidev.shop/api/health` через nginx хоста и шлюз.

Секреты репозитория: `SSH_HOST`, `SSH_USER`, `SSH_KEY`.

Разовая настройка сервера:

```bash
sudo mkdir -p /opt/dzen-inventory && sudo chown deploy:deploy /opt/dzen-inventory
git clone https://github.com/Blenemy/dzencode-test.git /opt/dzen-inventory
cd /opt/dzen-inventory && cp .env.example .env && chmod 600 .env
sudo cp deploy/host-nginx.conf /etc/nginx/sites-available/dzen
sudo ln -s /etc/nginx/sites-available/dzen /etc/nginx/sites-enabled/dzen
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d dzen.topchyidev.shop
```

В `.env` на сервере: свои пароли (`openssl rand -hex 32`), `PUBLIC_URL=https://dzen.topchyidev.shop`,
`GATEWAY_PORT=8090`, `TRUST_PROXY=2`, `COOKIE_SECURE=true`, свои `JWT_ACCESS_SECRET` и `JWT_REFRESH_SECRET`.
